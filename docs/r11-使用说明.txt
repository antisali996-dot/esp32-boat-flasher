ESP32 小船 / 遥控器 烧录配对工具（r11 适配版）
================================================================

适用：Windows 10 / 11，经典 ESP32 开发板（ESP32-WROOM / ESP32-D0WD，不是 S3 / C3）。
不需要安装 Python、Arduino IDE 或任何编译工具。全部解压即可用。

本包没有替你烧录任何板子，也没有改动板上现有程序。


一、本包里有哪两套固件
--------------------------------
本包含【两套已批准固件】，下拉框里可以明确选择：

  r11（默认选中）  版本 20261103-590rpm-r11，590 转 / 左右各 20°，
                   600 转超速锁存【已关闭】
  r10（保留对照）  版本 20261103-590rpm-r10，590 转 / 左右各 20°，
                   600 转超速锁存【已开启】

两套都只是 590 转目标，区别在超速锁存：r10 在 600 转时会软件锁存停机，
r11 取消了这个停机。默认选中的是 r11，但“下拉里选中的套装”不等于“板上正在跑的版本”；
板上实际版本一律以读到的 FWID 为准。


二、600 和超速锁存到底是什么（必读）
--------------------------------
r10：600 是【软件超速锁存阈值】。转速到 600 时固件会锁存并停机。
     这仍然只是软件阈值，不是物理转速上限的保证，也没有经过带载实测。

r11：600 超速锁存【已经关闭】。转速高于目标是靠 PI 正常降低输出，不会因为到 600 就停机。
     取消锁停【不代表】保证空载转速不超过 600，也【没有电流反馈】保证不过载。
     头文件里保留的 FW_OVERSPEED_RPM=600 只是历史数值，不参与任何停机判断。

旧固件如果没有明确的 OS 标记，工具显示“超速锁存状态未声明”，不猜成开启或关闭。


三、先读这四条
--------------------------------
1. 必须把 ZIP 全部解压到硬盘再运行，不要在压缩包里双击。
2. 烧录和配对前，断开动力电池和舵机电源，只保留 USB 给开发板供电。
   小船程序上电会自动把电机驱动到目标转速，不断动力就上电有危险。
3. 两套固件目标都是 590 转，都不是物理转速上限的保证。
4. 第一次读串口前会弹一次安全提示（同一次运行只出现一次），确认后再开始。


四、怎么确认板上是哪一版
--------------------------------
不要看文件名，也不要看 VERSION 文本，只看固件身份串 FWID：

  r11 小船    JAYFWB11-S20-A70-110-U1278-1500-1722-R590-OSOFF-Cr11-osoff
  r11 遥控器  JAYFWR11-S20-A70-110-U1278-1500-1722-D1750-2150
  r10 小船    JAYFWB10-S20-A70-110-U1278-1500-1722-R590-OS600-Cr10-diagshared
  r10 遥控器  JAYFWR10-S20-A70-110-U1278-1500-1722-D1750-2150

区别在 OS 段：r10 是 -OS600（锁存开启），r11 是 -OSOFF（锁存关闭）。
与本包任一清单都不符的一律按“不是最新”处理：工具会提示升级，不会当作已是最新。


五、界面
--------------------------------
顶部“固件套装”：下拉框每项都会写明锁存状态，例如
  「590 转 / 20° / 600 转超速锁存已关闭（版本 20261103-590rpm-r11）」
  「590 转 / 20° / 600 转软件超速锁存已开启（版本 20261103-590rpm-r10）」

串口列表：串口、板子角色、芯片 MAC、固件版本、转向角度、对端地址、说明。
读不到的项写“未知”，不会瞎猜。

主要按钮三个：烧录当前板、配对两块板、备份原固件。
配对行右侧还有一个「只读核验」，用于核验板子当前配置，不写任何东西。

勾选项两个：
- 烧录前先备份原固件（默认关闭，8MB 约 3～5 分钟）
- 即使已匹配也重刷


六、烧录当前板
--------------------------------
1. 选择串口，必要时选择这块板是小船还是遥控器（新板第一次必须选）。
2. 点“烧录当前板”。
3. 确认框会同时列出【板上现在】和【将写入】的角色、目标转速、转向角度、FWID，
   以及【超速锁存】变化。即使两侧都是 590 转，只要锁存不同也会明确写出来，例如：
     “超速锁存变化：板上【600 转软件超速锁存已开启】→ 将写入【600 转超速锁存已关闭】。
       写入后 600 不再触发停机；这不保证空载转速低于 600，也没有电流反馈保证不过载。”
4. 写入时强制校验；写完会重启并读回身份，两关都过才显示“烧录完成”。

- 板上固件已经与本包所选套装一致时，会提示“无需重复烧录”，不写入；
  要重刷请勾选“即使已匹配也重刷”。
- 写入失败、校验没报成功、重启读不回来，都算失败，不会显示成功。
- 写入四段：bootloader@0x1000、分区表@0x8000、OTA 选择@0xE000、应用@0x10000。
  不写 0x9000 起的 NVS，所以升级不会顺手抹掉保存的配对地址。
  注意：这只说明本工具的写入范围不覆盖 NVS，不等于“任意旧板的 NVS 升级保留”已经实测过。
- r10 ↔ r11 切换：两套目标转速都是 590，但超速锁存不同，确认框会单独提示这一差异。


七、配对两块板（重要）
--------------------------------
配对判据本轮没有放松：

- “JAY SAVED REBOOT”只表示保存回应收到，仅作为进展，不单独算成功，也不代表已证明重启。
- 保存后工具会重新发 JAY INFO，要求读到完整的 JAYv4 身份行，并逐项核对：
  角色、本机 MAC 等于写入前核对的芯片、PEER 等于本次目标、FWID 符合本轮固件。
- 只用 VERSION / STEER 不能替代 FWID；缺字段、半行、无法解析、MAC=READ_FAILED 全部不放行。
- 只有旧格式兼容行（无 FWID）不会作为核验依据。

看到以下任一提示时：
- 已保存但未确认生效（SAVED_ACK_NOT_QUEUED / SAVED_ACK_UNCONFIRMED）
- 超时／结果未知
- 失败／需要人工重新上电核验（含 BIND_BLOCKED_PENDING_ERROR）

请这样做：
1. 断开动力，重新上电；
2. 点「只读核验」，选择这块板，确认期望对端；
3. 只有读到完整、匹配的本轮身份，才会重新判定为已核对。

工具不会自动重复发送绑定，也不会把超时后迟到的成功文字当作本次成功。

双端完成条件（全部满足才显示“双端配对配置已核对”）：
- 写入前重新核对两个串口的角色与 MAC；
- 两个串口或两个 MAC 相同 → 禁止写入；
- 已正确的一端跳过绑定与重启（不会被顺手切换固件）；
- 需要改的一端按上面的状态链判定；
- 最后再查询两端：小船 PEER=本次遥控器 MAC、遥控器 PEER=本次小船 MAC，
  且两端都没有未解除的错误/未知状态。

r10 与 r11 能否交叉配对，按实际配对协议与转向契约判断：两套的配对协议都是 v2、
转向契约都是 20°/70～110°，所以工具不会仅因为版本号不同就要求重刷；
但工具也不会替用户假定兼容，最终以核对到的身份与地址为准。


八、备份原固件
--------------------------------
只读整片 Flash，不写不擦。文件保存在 `记录\日期时间-备份-角色\原固件.bin`，
旁边有 SHA256。备份含配对地址，自己留着，别发给别人。


九、分类包（B/C）
--------------------------------
本包如果是分类包，会带 `preset.json`，写明：
- 本组小船的芯片 MAC 与遥控器的芯片 MAC；
- 对应角色在本轮的 FWID（指向 r11）；
- 对应镜像哈希见 `构建记录\镜像哈希.txt`。

分类包在写入与绑定前会核对实际芯片地址：地址不符直接拒绝，不会写错板子。

  B 旧小船：小船 24:62:AB:F0:72:94，遥控器 24:62:AB:EF:CF:84
  C 新小船：小船 24:62:AB:F1:36:64，遥控器 24:62:AB:EF:CF:84

通用包（A）没有 preset.json，允许操作任意芯片，但仍按 MAC 核对身份。


十、现场诊断页
--------------------------------
诊断页只在「现场诊断」标签里，和烧录、配对、固件选择互不影响。

是否启用 JAY COUNT / JAY FAULT，取决于【板上实际 FWID】，不取决于下拉框选了哪套：

  r11 小船    COUNT ✓  FAULT ✓
  r10 小船    COUNT ✓  FAULT ✓
  r11 遥控器  无（固件未实现，零自动查询）
  r10 遥控器  无（同上）
  r9 及更早 / 未知 FWID  不查，只被动记录

- 白名单逐条按 FWID 登记，不用“前缀是 JAYFWB11 就全放行”的宽泛规则。
- 板上回 `JAY ERROR=UNSUPPORTED_COMMAND` 时立即停用该查询，不重复发送。

脚本格式：两端 r11 与 r10 的 COUNT / FAULT 输出格式逐字相同（已 diff 核对），
因此复用同一套解析核心，没有复制第二份解析器。

保留的严格规则：
- COUNT 用 64 位无符号解析，同时保留原始十进制文本。
- FAULT 的 rpm / integral 必须是合法有限浮点数（固定两位小数），
  id / ms / pulses / elapsed 为 uint32，pwm 为 int32；任何字段非法 → 整行“解析失败”，
  保留原文，不计入有效证据。
- 设备 + boot + id 严格关联；boot 未确认不判完整；冲突锁存；重复行不虚增组数。
- 原始字节逐字节落盘，导出逐条目核对 SHA256。


十一、验证边界（必读）
--------------------------------
本轮已完成：
- 从冻结快照（work/r11-input-20261103-193107）用 arduino-cli 1.5.1 / esp32:esp32 3.0.2
  重新编译两端，退出码均为 0。
- 两端 fw_identity.h 逐字节一致；FW_SCHEMA 11、FW_VER 20261103-590rpm-r11、
  FW_CONTROL_REV r11-osoff。
- 从实际应用镜像反读 FWID 与清单一致（小船含 -OSOFF，不含 -OS600）。
- 工具模拟测试 683 项全部通过，其中 r11 适配 71 项。
- r10 套装镜像与清单未改动（哈希与上一轮一致）。

本轮未验证：
- 未在真实 ESP32 上烧录、复位、读取；未连接任何设备。
- 未验证 r11 实机空载转速是否真的不超过 600（取消锁停不等于限速）。
- 未验证带载电流、过载保护、舵机实际角度、反复停启稳定性。
- 未验证 NVS 在真实升级后保留配对、真实断电后配对保持。
- 未验证 r10 与 r11 实机并存的完整配对流程与真实重启时序。
