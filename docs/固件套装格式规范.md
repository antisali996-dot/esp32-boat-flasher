固件套装格式规范（给源码端 / 打包端）
========================================

适用对象：负责编译固件、生成发布 ZIP 的一方。
工具端（本仓库）按本规范动态扫描固件库；满足规范的任何版本目录都会被识别，
不需要修改工具、不需要固定套装 ID。

一、目录结构
--------------------------------
把发布 ZIP 解压到工具旁的 `固件库\` 目录下，每个**直接子目录**就是一套固件：

  固件库\
    590-20-r11\            ← 套装目录（目录名任意，不参与版本判断）
      import.json          ← 必需：导入记录
      固件\
        固件清单.json       ← 必需：发布清单
        boat-app.bin        ← 小船应用镜像
        boat-bootloader.bin
        boat-partitions.bin
        remote-app.bin      ← 遥控器应用镜像
        remote-bootloader.bin
        remote-partitions.bin
        boot_app0.bin
      工具\
        esptool.exe         ← 必需：烧录组件
        GPL-2.0.txt / NOTICE.txt（许可证，建议带上）

多个版本可以并列：

  固件库\
    590-20-r10\
    590-20-r11\
    590-20-r12\            ← 未来版本，只要符合本规范即可
    my-custom-build\       ← 目录名任意

二、import.json（导入记录）
--------------------------------
工具用它确认这套固件的来源与版本，字段必须与固件清单一致：

  {
    "id": "590-20-r11",                  // 套装 ID，固件库内唯一（见第四节）
    "version": "20261103-590rpm-r11",    // 必须等于清单的 version
    "target_rpm": 590,                   // 必须等于清单的 target_rpm
    "steer_deg": 20,                     // 必须等于清单的 steer_deg
    "boat_fwid": "JAYFWB11-...",         // 必须等于清单 roles.BOAT.fwid
    "remote_fwid": "JAYFWR11-...",       // 必须等于清单 roles.REMOTE.fwid
    "overspeed_lockout": "off",          // 建议写，与清单一致
    "source": "说明来源",                 // 自由文本
    "manifest_sha256": "<清单文件 SHA256>",   // 建议写
    "boat_app_sha256": "<boat-app.bin SHA256>",   // 建议写，工具会回读核对
    "remote_app_sha256": "<remote-app.bin SHA256>"
  }

三、固件/固件清单.json（发布清单）
--------------------------------
  {
    "schema": 11,                        // 清单格式版本，工具要求 >= 3
    "version": "20261103-590rpm-r11",
    "steer_deg": 20,
    "angle_min": 70,
    "angle_max": 110,                    // 必须满足 angle_max - angle_min == 2 * steer_deg
    "center_us": 1500,
    "pulse_min_us": 1278,
    "pulse_max_us": 1722,
    "pair_protocol": 2,
    "target_rpm": 590,
    "overspeed_rpm": 600,                // 历史数值；r11 起不参与停机判断
    "overspeed_lockout": "off",          // 见第五节
    "diag_contract": "diag-v1",          // 见第六节（也可只写在角色内）
    "roles": {
      "BOAT": {
        "fwid": "JAYFWB11-S20-A70-110-U1278-1500-1722-R590-OSOFF-Cr11-osoff",
        "version": "20261103-590rpm-r11",
        "steer_deg": 20,
        "overspeed_lockout": "off",
        "diag_contract": "diag-v1",
        "app": "boat-app.bin",           // 相对路径，必须在本套装目录内（见第七节）
        "app_offset": 65536,             // 0x10000
        "bootloader": "boat-bootloader.bin",
        "bootloader_offset": 4096,       // 0x1000
        "partitions": "boat-partitions.bin",
        "partitions_offset": 32768,      // 0x8000
        "boot_app0": "boot_app0.bin",
        "boot_app0_offset": 57344        // 0xE000
      },
      "REMOTE": { ... 同结构 ... }
    }
  }

四、ID 唯一性与重复身份
--------------------------------
1. 套装 ID 在整个固件库内唯一（大小写不敏感）。两个目录写了同一个 id：
   两套都会被判不可用并明确提示，工具不会自动选一个。
2. 不同套装 ID、同角色 FWID 相同：
   - 镜像哈希也相同 → 允许并存，界面提示“同一镜像的两个发布套装”。
   - 镜像哈希不同 → 允许并存，界面提示“身份相同、镜像不同，板上 FWID 一致
     不能证明镜像一致”，由用户明确选择；重刷用“即使已匹配也重刷”。
3. 小船与遥控器 FWID 相同、角色错误、清单 FWID 不在镜像内：一律拒绝。

五、超速锁存声明
--------------------------------
`overspeed_lockout` 只有两个合法值：
  "on"  = 600 转软件超速锁存已开启（对应 FWID 含 -OS600）
  "off" = 600 转超速锁存已关闭（对应 FWID 含 -OSOFF）
FWID 里没有 OS 标记的旧固件显示“未声明”，工具不猜。
清单声明与 FWID 实际标记矛盾 → 套装判为不可用。
该字段只约束小船（遥控器没有电机，不参与判断）。

六、诊断契约（diag_contract）
--------------------------------
工具内部只登记已实现并测试过的协议契约。目前支持的契约：

  diag-v1：
    - JAY INFO / JAY PING（身份）
    - JAY COUNT boot=<boot> ms=<毫秒> total=<64位无符号>
    - JAY FAULT NONE / JAY FAULT CURRENT id=... name=... ms=... rpm=...（固定两位小数）
      pwm=... pulses=... elapsed=... integral=...
    - JAY FAULT PREVIOUS id=... （同上，无 name）
    - JAY ERROR=UNSUPPORTED_COMMAND → 工具停用对应查询

新固件包如果要启用自动诊断查询，请在清单里为对应角色写：
  "diag_contract": "diag-v1"
并且 FWID 必须与镜像内嵌身份完全一致。工具运行时按
「板上实际 FWID == 清单 FWID」+「契约已支持」双条件启用，不按版本前缀放行。

如果新固件改变了输出格式，必须先与工具端协商新契约 ID（例如 diag-v2），
由工具端实现并测试后才能启用；未知契约的固件仍可正常烧录，只是诊断只被动记录。

注意：清单里的契约声明不能包含任何可执行脚本或任意串口命令；
工具只会发送上面列出的固定只读查询。

七、路径安全
--------------------------------
清单里的所有镜像路径必须：
  - 是相对路径（相对本套装的 固件\ 目录）；
  - 不含 `..` 或 `.` 段、不含 `~`、不是绝对路径或 UNC 路径。
违反任何一条 → 套装不可用。

八、哪些字段更新后必须重新生成校验
--------------------------------
改了下面任何一项，都必须重新编译两端、更新 import.json 的对应哈希字段，
并重新生成 文件校验.json（工具端打包脚本会做）：
  - fw_identity.h 的任何宏（FWID 会变）；
  - 任一镜像内容；
  - 清单里的 fwid / version / app 哈希类字段；
  - import.json 的 id / version / *_fwid / *_sha256。

九、打包与交付流程
--------------------------------
1. 源码端编译两端，产出 7 个镜像文件（两端各 app/bootloader/partitions + boot_app0）。
2. 按第二节、第三节生成 import.json 与 固件/固件清单.json（字段必须互洽，
   工具加载时会交叉核对，不一致直接判套装不可用）。
3. 把整套目录压成一个 ZIP，命名建议 `590-20-rNN-日期.zip`。
4. 用户把 ZIP 解压到工具旁 `固件库\`，点工具界面的「刷新固件库」即可；
   或者重启工具。不需要修改工具程序，不需要改 JSON 之外的东西。

十、工具端行为摘要（供核对）
--------------------------------
- 每个直接子目录一套；ID/版本/角色/FWID/地址全部来自 import.json 与清单，
  不按目录名猜版本。
- 一套损坏只影响该套，其它有效套装继续可用。
- 缺文件、哈希不符、身份矛盾、分区不安全（NVS 被写入范围覆盖）一律拒绝。
- 烧录前工具会再核对所选套装的清单版本与镜像哈希（与加载时快照比较），
  检测“刷新后被替换”的情况。
