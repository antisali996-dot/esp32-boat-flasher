ESP32 现场诊断（只收集证据，不下结论）
========================================

适用：Windows 10 / 11。本页只在「现场诊断」标签页里，和原来的烧录、配对、固件选择互不影响。


一、这个页面能做什么
--------------------------------
按顺序四个主要操作：

1. 连接并核对版本
   打开所选串口（DTR=false、RTS=false），只发一次 JAY INFO 读取身份。
   显示角色、自身 MAC、FWID。读不到的项显示“未知”。

2. 开始记录
   只有“已连接”状态才能开始。开始后收到的数据先原样写入本地原始字节文件，
   再做解码与解析；解析失败不会丢数据。

3. 标记异常
   只有三种：电机停下、电机重新启动、舵机微动。
   标记只写本地文件，不发任何串口命令，不改电机、舵机、配对或参数。
   不需要现场手数 10 圈。

4. 停止并导出
   先停止查询与采集、刷新已接收数据，再生成 ZIP。
   ZIP 会先写成临时文件并校验（能打开、文件齐全、清单哈希一致）才报告完成。
   导出失败不删原始记录，可以重试；取消保存位置也保留本地会话。


二、状态
--------------------------------
未连接 → 已连接 → 记录中 → 已停止／导出中 → 已导出
另有：连接失败、掉线、等待重新连接、导出失败。

- 掉线会保留当前会话与全部已写入文件，不会自动清空，也不会另起一个覆盖旧文件的新会话。
- 重新连接后必须重新读取身份；MAC 变化会建立新的设备分段并明确提示，不会无提示续接。
- 串口切换（例如 COM8 → COM9）会把锁一起迁移：新串口先取锁，取不到就拒绝，不会带锁失败。
- 停止记录后不再发送任何查询命令。


三、串口与只读限制
--------------------------------
- 打开串口前设置 DTR=false、RTS=false。
- 诊断不调用 esptool，不发送烧录、擦除、JAY BIND 或参数修改命令。
- 不主动触发板子复位。
- 串口被占用、读取异常、断开与重连，都会记录电脑时间和错误原文。
- 遇到串口错误不会自动发送控制命令去“恢复”。
- 记录期间，同一串口在核心层被锁定：烧录、配对、重新扫描都会被拒绝，界面按钮禁用只是第二道保护。

重要：软件保持 DTR、RTS 为 false，但不能保证所有 USB 串口硬件在打开连接时都绝不复位。
这是硬件/驱动行为，工具无法控制。


四、接口状态（r10）
--------------------------------
固件身份行按 JAYv4 解析。是否启用 JAY COUNT / JAY FAULT 由固件身份串 FWID 白名单决定，
并且按角色分开批准。r10 的能力表是：

  小船 r10    COUNT ✓   FAULT ✓
  遥控器 r10  无        无        ← 固件未实现，工具零自动查询
  r9 及更早   不查       不查      ← 不在白名单
  未知 FWID  不查       不查      ← 不在白名单

界面会明确显示当前属于哪一种：
- “接口支持：已确认白名单（记录中会低频查询 COUNT/FAULT）”
- “接口支持：遥控器不提供 COUNT/FAULT（只被动记录）”
- “接口支持：未确认（只被动记录，不自动发送 COUNT/FAULT）”

启用后：记录开始后每 5 秒串行查询一次 COUNT 和一次 FAULT；不重叠、不堆积；
同一查询超时不重发，等下一周期；掉线或停止记录立即取消后续查询。
若板子回 `JAY ERROR=UNSUPPORTED_COMMAND`，对应查询立即停用且不再重发，直到重新连接/重新开始记录。


五、COUNT 格式与规则
--------------------------------
`JAY COUNT boot=<启动标识> ms=<采样毫秒> total=<64位累计计数>`

- boot 按原始文本保存，不假定为整数或终身唯一。
- total 用 64 位无符号整数解析，同时保存原始十进制文本；两者都写进 CSV。
- 超出 64 位、缺字段或非法数字：保留原文并标记解析失败，不猜测数值。
- boot 改变 → 新建启动分段；同 boot 下计数倒退只记录异常，不认定重启。
- ms 是设备自己的毫秒计数，和电脑接收时间分别保存，不混成一个时间轴。
- 本轮不新增 RPM、PPR 或圈数推导，只保存累计计数快照。


六、FAULT 格式与关联规则
--------------------------------
r10 正式格式：

  `JAY FAULT CURRENT id=<编号> name=<名字> ms=<毫秒> rpm=<转速> pwm=<值> pulses=<脉冲数> elapsed=<已运行毫秒> integral=<积分>`
  `JAY FAULT PREVIOUS id=<编号> ms=<毫秒> rpm=<转速> pwm=<值> pulses=<脉冲数> elapsed=<已运行毫秒> integral=<积分>`
  `JAY FAULT NONE`

- 只识别以上三种前缀。其它写法保留原文，标为“待适配（未识别格式）”，不硬套进字段。
- CURRENT 带 name（固件内部故障名），PREVIOUS 不带 name；PREVIOUS 的 name 留空。

故障证据状态（界面和导出都能区分）：

  待适配          未识别格式（原文保留，不参与关联）
  解析失败        前缀对得上但某个数字字段非法（原文与失败字段都保留，不参与关联）
  设备分段未确认  该行来自“待归属”分段，还没确认是哪块板
  启动分段未确认  boot 缺失或是内部占位值
  不完整          CURRENT / PREVIOUS 缺一行（会写明缺哪一行）
  完整            两行配套且下面六条全部成立
  冲突            同一关联键出现内容不同的同类型行
  无故障报告      JAY FAULT NONE

“完整”必须同时满足：
  1. 来源设备分段已确认（不是“未识别”、不是“待归属”）；
  2. boot 已确认（不是空、不是 unknown / boot-unknown / ? / - 这些占位值）；
  3. id 有效（非空）；
  4. CURRENT 与 PREVIOUS 属于同一设备、同一已确认 boot、同一 id；
  5. 两种行都已收到；
  6. 该关联组没有冲突行。

只要任一条不满足，就不会显示“完整”。

字段数值校验（本轮新增，依据已批准 r10 快照的实际类型）：

  字段      固件类型     输出格式   接受范围
  id        uint32       %lu        0 … 4294967295
  ms        uint32       %lu        0 … 4294967295
  pwm       int32        %ld        -2147483648 … 2147483647（允许负，表示反转）
  pulses    uint32       %lu        0 … 4294967295
  elapsed   uint32       %lu        0 … 4294967295
  rpm       float        %.2f       有限值，固定两位小数，允许负
  integral  float        %.2f       有限值，固定两位小数，允许负

- 全部按 InvariantCulture 解析，不受电脑区域设置影响；逗号小数点（如 612,40）按协议判失败。
- 拒绝：多个小数点（1.2.3）、只有小数点（.）、只有负号（-）、空值、NaN、Infinity、
  非数字字符、整数越界、小数位不是两位。
- 不补零、不截断、不猜测数值。
- 任一必需字段非法 → 整行判“解析失败”：保留完整原文，写明是哪个字段、什么原因，
  HasFields 为 false，不提交给关联，不补齐、不覆盖、不解除已有组。

关联键 = 确认设备分段 + 确认启动分段 + id。规则：
- 不再把所有未知 boot 塞进一个 "boot-unknown" 键去拼完整；boot 未知时两行都保留原文、
  状态固定为“启动分段未确认”。
- 之后即使收到 COUNT 带来 boot，也不会回头把之前 boot 未知的 FAULT 补成完整。
- 待归属分段里的 FAULT，在设备和 boot 确认前不会晋升为完整。
- 跨设备、跨 boot、跨 id 一律不合并。
- PREVIOUS 先到、CURRENT 后到，只要关联条件成立，同样能形成完整证据。
- 完全相同的同类型行重复到达：原始日志逐次保存，组内去重，不算冲突，也不增加完整组数。
- 同键同类型出现不同有效内容：状态锁定为“冲突”，保留全部候选原文，
  不会静默挑第一条/最后一条/数值更大的那条当完整证据。
- 冲突一旦锁存，后续再收到旧行、另一类型行或 NONE，都不会把它恢复成完整。
- JAY FAULT NONE 单独记录，不删除、不覆盖、不解除历史故障与冲突。

“证据完整”只表示两行配套齐全，不代表故障根因成立、动作被验证或问题已解决。

七、记录内容
--------------------------------
每个会话目录（`诊断记录\诊断-时间-随机码\`）包含：

- `设备分段\<角色-MAC>\raw.bin`：原始接收字节，逐字节保存。
- `接收索引.csv`：电脑接收时间（带时区）、单调接收序号、设备分段、启动分段、文件、字节偏移、长度、分块 SHA256。
- `设备分段\<角色-MAC>\解码文本.log`：可阅读的 UTF-8 解码文本。
- `异常标记.csv`：类型、电脑时间、会话、设备分段、附近接收序号。
- `身份记录.csv`、`COUNT快照.csv`、`FAULT快照.csv`、`事件.csv`、`查询记录.csv`、`采集错误.csv`、`待归属分段关联.csv`。
- 导出时新增：`导出说明.txt`（版本、起止时间、时区、统计）、`文件清单与SHA256.txt`。

规定：
- 收到的数据不会因为“解析失败／不是完整行／未知字段”被丢弃。
- 流式解码：中文可跨接收块，身份行可跨块，一次多行与结尾无换行的残行都会保留。
- 解码出错不影响原始字节文件。
- 板上 ms、boot 标识与电脑接收时间分别保存，不混成一个时间轴。
- 本工具只承诺保存“实际接收到的数据”，不能证明设备从未丢日志。


八、导出内容
--------------------------------
ZIP 里至少有：原始字节与全部分段、接收索引、可阅读日志、异常标记、
身份记录与 FWID、COUNT 快照、FAULT 快照及配对状态、掉线/重连/重启证据、
查询记录、工具版本与采集起止时间（含时区）、采集错误与可能缺口说明、文件清单与 SHA256。

导出不包含根因结论，也不会写“问题已解决”。


九、常见问题
--------------------------------
没有串口：换 USB 数据线；确认 CH340 驱动；关闭占用串口的其它程序。
连接失败：可能串口被占用，或板子没有回应身份。错误原文会出现在诊断过程里。
掉线：已写入的文件不会丢；重新连接会重新读取身份，MAC 变化会新建分段。
导出失败：原始记录仍在，可以再点一次“停止并导出”。
遥控器没有 COUNT/FAULT：正常，r10 遥控器固件未实现这两个命令，工具不会去试探。


十、r10 故障关联修复（本轮）
--------------------------------
针对主协调端复现的三个问题：

1. boot 为空时 CURRENT+PREVIOUS 被判完整 → 现在判“启动分段未确认”，不判完整。
2. 同设备同 boot 同 id 出现两条内容不同的 CURRENT 再加 PREVIOUS 仍判完整
   → 现在锁定“冲突”，保留两种 CURRENT 原文，不判完整。
3. 正常两行经实际采集后仍停留在“待适配”、互相声称缺另一行
   → 现在经正式采集路径形成真实关联组：先到的一行显示“不完整（缺 PREVIOUS）”，
     另一行到达后同一组变为“完整”。

状态模型不再用一个“待适配”表示所有情况，区分：
待适配 / 设备分段未确认 / 启动分段未确认 / 不完整 / 完整 / 冲突 / 无故障报告。

正式采集接入（DiagnosticsController.Pump，与测试、导出共用同一套 FaultRegistry）：
原始字节落盘 → 完整行 → r10 适配器解析 → 带设备分段/启动分段/接收序号/电脑时间
→ 更新关联状态 → 立即落盘 FAULT关联.csv 与 FAULT关联状态变化.csv → 更新界面标签。

新增导出文件（都进文件清单与 SHA256 核验）：
- FAULT关联.csv：每组的状态、设备/boot 确认标记、id、缺行说明、冲突原因、
  CURRENT/PREVIOUS 接收序号、两行原文（冲突时为全部候选原文）。
- FAULT关联状态变化.csv：每次状态迁移的时间、前后状态与原因。
- 导出说明.txt 增加“故障关联”汇总段，从磁盘记录重建，不依赖内存近期窗口。

内存边界：关联登记表最多 2000 组；每组每类型最多保存 8 条不同内容代表行。
达到上限时明确写入 capacity_limit 说明，原始行仍全部落盘，历史不会因此消失。

测试：原有 154 + 52 + 61 + 74 + 50 + 33 + 29 项继续通过；
故障关联修复 86 项继续通过；新增 73 项 FAULT 数值校验测试全部通过（共 612 项）。

十一、本轮修复：FAULT 非法数字不再被当作有效证据
--------------------------------
主协调端复现：CURRENT 里 rpm=... / integral=.. 被判为有效，再收到同组 PREVIOUS 后
显示“完整 1 组”。原因是正则 -?[\d.]+ 允许多个小数点，且只保存字符串、不做数值校验。

修复后：
- 正则收窄为“定点两位小数”与“有符号/无符号整数”的实际形状；
- 每个字段再按 uint32 / int32 / float 做数值合法性与范围校验（InvariantCulture）；
- 任一字段非法 → 整行 Malformed：保留原文、写明字段与原因、不进入关联、不影响已有组；
- 冲突比较改用校验通过的数值，避免数值相同但文本排版不同被误判为冲突；
- 导出说明新增“解析失败行数”与涉及字段统计，明细在 FAULT快照.csv。

通过实际采集路径验证（FakeDiagChannel → DiagnosticsController.Pump）：
非法 CURRENT + 合法 PREVIOUS 时完整组数为 0，PREVIOUS 停在“不完整（缺 CURRENT）”。

十二、边界（必读）
--------------------------------
可靠遥控自动恢复仍未完成；600 只是软件阈值；超速、舵机微动和反复停启三个现场问题
仍无实机验证结论。现场诊断用于收集证据，不代表已找到根因、解决问题或通过比赛验收。
