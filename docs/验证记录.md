# 验证记录（多固件套装版本）

本文件只记录实际做过的事。没有做过的实机验证列在最后一节，不能把它当作设备验证。
拆分基线的验证另见 `docs/迁移验证记录.md`。

## 1. 独立构建

- 命令：`powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1`
- 使用 Windows 自带 .NET Framework 编译器（csc 4.8），目标 anycpu，不依赖固件工程、Arduino CLI 或 Python。
- 产物：`work/build/ESP32小船烧录工具.exe`、`work/build/模拟测试.exe`。
- 不复制、不修改 `boat/`、`remote/` 源码；不调用 Arduino 编译；固件只从 `firmware-library` 导入。

## 2. 模拟测试（138 项，全部通过）

运行：`.\work\build\模拟测试.exe`，完整输出见 `tests/sim-test-record.txt`。
全部使用 `IBoardTransport` 的内存实现与工程内临时目录，不打开任何真实串口。

覆盖内容：

1. 身份行解析：v3 带 FWID、旧格式无 FWID、旧格式自称 STEER=20 仍无 FWID、多行优先取带 FWID 的行、拒绝多播 MAC。
2. FWID 解析：小船 580/590 的角色与转速、590 超速字段、遥控器 FWID 不被误解析出转速、20° 与 30° 契约区分。
3. 版本判断：同 FWID 为最新；旧 30° 需升级；FWID 不同需升级；角色不符拦截；配对协议版本不作为新旧依据；
   590 板对 580 套装需切换、对 590 套装一致。
4. 分区布局：正常分区识别出 NVS 0x9000；NVS 与应用区重叠、缺 NVS、应用越界、缺文件四种情况都被判不兼容。
5. 固件库加载：两套都可用，转速/角度/版本取自清单；按 FWID 找套装；未知 FWID 不归属；
   清单被篡改（转速不符）、镜像被替换（FWID 不符）、目录名误导（目录叫 590 清单是 580）都被正确处理。
6. 镜像混用拦截：两套共用同一小船 FWID 被标记；小船与遥控器指向同一应用镜像被拦下。
7. 角色记忆：只按 MAC；同串口可记两块板；持久化；未知 MAC 不猜；记忆文件损坏不猜。
8. 串口换插：同一 COM8 换板后读到新 MAC、角色随 MAC 变化；误选角色被拒绝且不写入。
9. 新板首次使用：不选用途拒绝烧录；选定后成功并记住；换到新串口角色仍按 MAC 保持；空串口不挂旧身份。
10. 默认不备份：不读整片 Flash、仍写入校验、只确认一次、确认框同时给出板上与将写入信息。
11. 可选备份：勾选后整片备份留档；单独备份只读不写、备份前核对 MAC。
12. 写入失败：写入失败返回失败；缺少 `Hash of data verified` 也算失败。
13. 烧录前复核：确认框期间换插另一块板被拦截且不写入。
14. 两套切换：580→590 写入 590 的 FWID、确认框提示跨套装并列出两套名称；590→580 同样正确；
    缺镜像的套装判为不可用。
15. 已匹配套装：提示“无需重复烧录”、不弹确认框、不写入；勾选“即使已匹配也重刷”后写入并在确认框标注。
16. 误降级：590 板写 580 套装被标记降级，提示里写明 590 与 580；取消确认则不写入、板子状态不变。
17. 套装隔离：写入时使用所选套装自己的 esptool 路径。
18. 双板配对：一次完成双方、只改地址不重刷、不备份、两端地址互指、记住角色、只确认一次。
19. 配对拦截：同一串口被拒绝；不同串口但同一 MAC 被拒绝且不写入。
20. 部分失败与重试：标记部分完成并说明 1/2；重试只写未完成的一端；
    一端失败仍尝试另一端，失败端保持原样并列出待处理项。
21. 跳过已正确端：小船已正确时只写遥控器，已正确端不出现在写入事件里；结果与确认框都标明跳过；
    两端都正确时零写入、明确说明没有改写。
22. 跨速兼容配对：590 小船 + 同一 20° 遥控器允许配对，不写固件，说明里写明转向契约一致、遥控器不控制油门。
23. 契约/协议不符：30° 与 20° 拒绝配对；配对协议版本不同拒绝配对。
24. 旧固件：无 FWID 拒绝配对并提示升级；一端无回应不当作成功。
25. 安全提示：两次操作只提示一次；拒绝提示则不扫描、不访问串口。
26. 清单自检：正常清单通过；镜像缺 FWID 被拦下；清单角度与 FWID 契约不一致被拦下。
27. 无身份旧板：读芯片 MAC 回退、显示旧版、仍要求用户选角色、升级成功且默认不备份、升级后记住角色。
28. 烧录后读回：写入接口报成功但读回身份不符时返回失败。
29. 写入方式：四个分段镜像、不整片覆盖 0x0；确认框写明 NVS 不写入。
30. 分区不兼容：该套装判为不可用，选中后拒绝写入且不声称保留成功。
31. 缺烧录组件：缺 esptool 的套装判为不可用；未选套装时扫描旧板仍能借用可用套装的组件。
32. 身份行前向兼容：JAYv4 行按同一字段解析并记录版本号（3/4），旧 JAY ROLE= 记为 0，
    不会把升版后的新固件误判成“无身份”。

## 3. 用真实发布包做的检查

`firmware-library` 里的两套是本地导入的真实发布包（未放入 Git）：

- 580-20-r3：`20261103-20deg-r3`，580 转，小船 `JAYFWB3-S20-A70-110-U1278-1500-1722-R580-C580pi2`，
  遥控器 `JAYFWR3-S20-A70-110-U1278-1500-1722-D1750-2150`。
- 590-20-r4：`20261103-590rpm-r4`，590 转 / 超速 600，小船
  `JAYFWB4-S20-A70-110-U1278-1500-1722-R590-OS600-Cpi2-aw-os600`，遥控器
  `JAYFWR4-S20-A70-110-U1278-1500-1722-D1750-2150`。

包内自检（`--self-check`，不打开串口）：两套都判为可用，各自解析出 NVS 0x9000 +0x5000（工具不写入），
镜像内确实存在清单声明的 FWID。打包脚本另外逐套复核了“清单 FWID 出现在应用镜像内”，两套均一致。

## 4. 打包验收

`scripts/package.ps1` 流程：编译 → 从 firmware-library 组包 → 包内自检 → 生成 SHA256 →
压缩 → 解压 → 再自检 → 逐文件比对 SHA256 → 逐套核对镜像 FWID。

最近一次：32 个文件全部一致；两套镜像 FWID 与清单一致；ZIP 14.64 MB（15,355,151 字节）。
`自检报告.txt` 与 `文件校验.json` 不参与自身校验（前者含运行路径、后者是清单本身）；
整片 `merged.bin` 不打包，避免被误当成可整片覆盖的镜像。
